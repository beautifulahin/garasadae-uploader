# 가라사대 업로더 — 개발 문서

지정한 폴더에 영상 파일이 저장되면 유튜브에 자동으로 올려주는 프로그램.
맥·윈도우 모두 동작하며, 받는 사람은 아무것도 설치하지 않아도 된다.

## 구조

2.0.0 에서 안쪽을 통째로 새 방식으로 바꿨다 — 파이썬으로 만든 「현재 업로더」(받는 곳 → 채널 폴더 → 쪽지 → 발사대기 → 비공개 업로드 → 30분 심사 → 공개)의
구동·작동·인증 방식을 Deno/TypeScript 한 벌로 다시 짰다. 겉모습(`app/ui.html` 과 `app/ui/`)은 옛 화면의 틀과 색을 그대로 쓴다.

### 데이터 폴더 (사용자 컴퓨터)

`~/Library/Application Support/가라사대업로더/` (맥) · `%APPDATA%\가라사대업로더\` (윈도우). `GARASADAE_DATA_DIR` 로 바꿀 수 있다 (시험).
파이썬 업로더와 같은 이름·모양을 쓴다: `channels.json`(채널 칸) · `tokens.json`(로그인 정보, 권한 600) · `ledger.csv`(올린 기록) · `발사대기.json` · `pending.json`(심사 대기) · `*_daily_policy.json`(하루 한도 정책) · `client_secret*.json`(내 열쇠).
이 앱만의 것: `앱설정.json`(권한 600 — AI 열쇠) · `쿠팡파트너스.json`(권한 600) · `인증상태.json` · `AI문안기록.json` · `채널말투표본.json` · `이행기록.json` · `이행보류.json` · `백업/이행전_날짜_시각/`(옛 자료 복사본) · `기록/`(로그).

## 개발

```bash
deno run -A --no-lock app/main.ts              # 화면까지 열림
deno run -A --no-lock app/main.ts --background # 브라우저 없이
./시험실행.sh                                  # 진짜 설정·포트와 따로 (임시 폴더 + 다른 포트)
TZ=Asia/Seoul deno run -A --no-lock 논리시험.ts   # 전체 논리 시험 (이름을 주면 그것만: 이식 · 이행안전 · 서버 …) — 일부 기대값이 한국 시각을 쓰므로 TZ 를 맞춘다(점검.sh 가 알아서 맞춘다)
./점검.sh                                      # 빌드 전 관문 전체
```

시험은 구글·유튜브·쿠팡·Google AI 에 한 번도 닿지 않는다 — 가짜 서버(`시험/가짜구글.ts`, 시험마다 `setFetch`)와 임시 폴더(`시험/도구.ts` 의 `모래상자`)만 쓴다.
진짜 집 폴더·환경변수·자동 시작은 건드리지 않는다 (`GARASADAE_HOME` · `setFinderEnv` · 가짜 명령 실행기).
`deno run -A --no-lock 논리시험.ts 브라우저` 는 진짜 서버를 임시 상자에 띄우고 헤드리스 크롬으로 진짜 화면을 사람처럼 눌러 본다(탭 일곱 · 담기→올리기 · 열쇠 찾기 · 이행 보류 띠 · 자바스크립트 오류 없음) — 크롬이 없으면 건너뛰고, 기본 시험 모음에는 들어 있지 않다.
`시험/화면모의서버.ts` 는 화면 일꾼이 서버 없이 화면을 시험하던 모의 서버(`시험/모의/api_*.json`)이고, `시험/화면약속.ts` 가 그 모의 응답의 칸이 진짜 서버 응답에도 있는지 견준다.

## 빌드 · 배포

```bash
./build.sh
```

맥에서 실행해도 윈도우용 `.exe` 까지 함께 나온다. `dist/*.zip` 을 그대로 배포하면 된다.

| 파일 | 대상 |
|---|---|
| `garasadae-uploader-mac-apple-silicon.zip` | M1 이후 맥 |
| `garasadae-uploader-mac-intel.zip` | 2020년 이전 인텔 맥 |
| `garasadae-uploader-windows.zip` | 윈도우 10 / 11 (64비트) |

**이름을 바꾸지 말고 그대로 올린다.** 자동 업데이트가 이 이름으로 내려받기 때문에
(`app/update.ts` 의 `assetName()`), 이름이 어긋나면 배포는 되는데 업데이트만 조용히 멈춘다.
`build.sh` 가 마지막에 `update.ts` 와 이름을 대조해 다르면 빌드를 세운다.

```bash
gh release create v1.2.3 --title "가라사대 업로더 1.2.3" \
  --notes-file 배포/릴리스노트_1.2.3.md dist/*.zip
```

### 주의사항

- 맥 번들 안의 실행파일 이름은 반드시 **ASCII** 여야 한다 (`GarasadaeUploader`).
  한글 이름을 쓰면 코드서명 봉인이 깨져 `a sealed resource is missing or invalid` 가 난다.
  `.app` 폴더 이름 자체는 한글이어도 된다.
- 애드혹 서명이라 공증(notarization)은 되어 있지 않다. 공증하려면 애플 개발자 계정(연 $99)이 필요하다.
  - **macOS 15(Sequoia)부터 「오른쪽 클릭 → 열기」 우회가 없어졌다.** 뜨는 창은
    「'가라사대 업로더'을(를) 열지 않음」 이고 버튼이 **[휴지통으로 이동] · [완료]** 둘뿐이라 열 길이 없다.
    받는 사람은 **[완료]** 를 누른 뒤 **시스템 설정 → 개인정보 보호 및 보안** 아래쪽의
    **[무시하고 열기]** 를 눌러야 한다.
  - macOS 14 이하는 여전히 **오른쪽 클릭 → 열기** 로 넘어간다. 윈도우는 **추가 정보 → 실행**.

### 그 창의 뿌리는 서명이 아니라 「격리 표」다 (2026-09-02 실측)

Gatekeeper 가 앱을 검사하는 방아쇠는 파일에 붙은 **`com.apple.quarantine` 확장속성(격리 표)** 이다.
이 표를 붙이는 것은 **앱이 아니라 받아 온 프로그램**이다.

| 어떻게 받았나 | 확장속성 | 결과 |
|---|---|---|
| 크롬으로 zip 내려받기 | `com.apple.quarantine: 0281;…;Chrome` + `com.apple.provenance` | 「열지 않음」 창이 뜬다 |
| `curl` 로 내려받기 | `com.apple.provenance` **하나뿐** | 창이 뜨지 않는다 |

즉 **공증에 돈을 쓰지 않아도, 격리 표가 안 붙게 받으면 창 자체가 뜨지 않는다.**
그래서 첫째 길은 터미널 한 줄이다.

```
curl -fsSL https://beautifulahin.github.io/garasadae-uploader/install.sh | bash
```

- 그 한 줄이 실행하는 것이 **`docs/install.sh`** 다.
  다만 **그 주소는 `docs/` 가 아니라 `gh-pages` 가지에서 나온다** — 아래 「문서 사이트」 항목을 볼 것.
  칩 판별(로제타 안에서도 `sysctl -n hw.optional.arm64` 로 진짜 하드웨어를 본다) → `curl -fL` 로 받기
  → `ditto -x -k` 로 풀기(권한·서명 보존, `unzip` 이면 깨진다) → `/Applications` 에 `ditto` 로 놓기
  → `xattr -dr` 안전벨트 → `open` 까지 한다.
  이미 깔린 앱은 **지우지 않고** `~/.가라사대업로더_이전/<날짜_시각>/` 로 옮긴다.
- **릴리스를 새로 올려도 `install.sh` 는 손댈 필요가 없다.**
  버전 없는 `releases/latest/download/<자산이름>` 주소를 쓰기 때문에 늘 최신을 받는다.
  자산 이름을 바꾸면 그때만 같이 고친다(= `build.sh` · `app/update.ts` 와 같은 이름).
- **앱을 다시 구울 필요도 없다.** `install.sh` 는 지금 올라가 있는 릴리스(v1.8.1)를 그대로 받아 깐다.
  한 줄 설치를 살리는 데 필요한 것은 `install.sh` 를 문서 사이트에 올리는 것 하나뿐이다.
- **파이프로 bash 에 먹이므로 `read` 로 사용자 입력을 받으면 안 된다** — stdin 이 스크립트 자신이다.
  그리고 bash 는 변수 이름에 한글을 쓸 수 없어 `"「$APP_NAME」"` 처럼 쓰면
  `APP_NAME」` 을 변수로 읽어 `set -u` 에서 죽는다. 반드시 `${APP_NAME}` 로 감싼다
  (2026-09-02 실제로 이 버그가 났고 시험에서 잡았다).
- zip 을 이미 받은 사람을 위해 맥 배포물에는 `배포/열기.command` 를 계속 함께 넣는다
  (build.sh 의 「안내문 동봉」 단계). `xattr -dr com.apple.quarantine` 로 격리 표만 벗기고 `open` 한다.
  더블클릭으로 돌아야 하므로 **실행권한 755 를 반드시 유지**한다 —
  zip 은 권한을 보존하는 `zip` 명령으로 묶는다.
- 문서에 적은 차례는 어디서나 같다: **① 한 줄 설치 → ② 열기.command → ③ 손으로 4단계 → ④ 옛 맥(14 이하)**.
  (`README.md` · `docs/index.html` · `docs/설정안내.md` · `docs/errors.html` · `배포/맥_처음읽어주세요.txt`)

## 문서 사이트 — `docs/` 가 아니라 `gh-pages` 가지다

`https://beautifulahin.github.io/garasadae-uploader/` 의 소스는 **`gh-pages` 라는 딴 가지**다
(깃허브 Pages 설정: `branch: gh-pages, path: /`). **`main` 의 `docs/` 폴더가 아니다.**

```
gh-pages 에 든 것 : .nojekyll · index.html · errors.html · privacy.html · terms.html
```

- **2026-09-02 이전에는 사람이 손으로 옮겼다.** 옮기는 절차가 어디에도 적혀 있지 않았고
  (`.github/workflows` 없음 · 문서에 gh-pages 언급 0건), 그래서 `main` 의 `docs/` 를 고쳐도
  사이트는 낡은 채로 남았다. 이번 「열지 않음」 사고가 커진 한 축이 이것이다.
- **이제 `릴리스.sh` 가 자동으로 올린다.** `gh release create` 가 끝난 **뒤에**
  `docs/*.html` 과 `docs/install.sh` 를 `gh-pages` 에 올린다.
  - `git worktree` 로 `gh-pages` 를 임시 폴더에 붙여 쓰고 끝나면 뗀다 —
    **작업 폴더의 가지를 갈아타지 않는다.**
  - `.nojekyll` 은 건드리지 않는다. 바뀐 것이 없으면 커밋하지 않는다.
  - 여기서 실패해도 **이미 올라간 릴리스는 되돌리지 않는다.** 손으로 올리는 명령을 한글로 찍고 끝낸다.
- 그래서 `install.sh` 를 고쳤으면 **릴리스를 한 번 돌려야** 주소에 반영된다.
  릴리스 없이 문서만 급히 올려야 하면 `릴리스.sh` 가 찍어 주는 명령을 그대로 손으로 치면 된다.

## 구글 로그인 열쇠

**기본**: 배포본에는 구글 로그인 열쇠(데스크톱 유형 + TV 유형)가 **실행 파일 안에만** 묶여 있다. 사용자는 구글 클라우드 프로젝트를 만들 필요 없이 로그인만 한다.
- 열쇠 값은 **소스·git·문서·시험·로그 어디에도 없다.** `build.sh` 가 굽는 동안만 `build/.client/` 에 복사해 `deno compile --include build/.client` 로 묶고, 굽고 나면(성공이든 실패든) 지운다.
  열쇠가 든 폴더의 자리는 환경변수 `GARASADAE_CLIENT_DIR` 또는 `배포/.클라이언트경로`(한 줄 짜리 파일, `.gitignore`)로만 알려 준다. 열쇠 없이 구우면 열쇠 없는 판이 되고, 그 판은 사용자가 열쇠 파일을 넣어야 로그인된다.
- `점검.sh` 가 추적되는(그리고 곧 올라갈) 모든 파일에서 열쇠 모양(`GOCSPX-…` · `….apps.googleusercontent.com` · 프로젝트 번호)과, 원본 열쇠 파일이 있으면 그 **실제 값**을 찾아 하나라도 걸리면 빌드를 세운다. 값은 출력하지 않는다.
- 권한은 세 가지: `youtube.upload` · `youtube.readonly` · `youtube`(공개 전환에 필요 — `force-ssl` 은 코드 인증이 받아 주지 않아 쓰지 않는다).

**내 열쇠**: 채널마다 전용 열쇠 파일(`client_secret_<이름>.json`)을 지정할 수 있고(토큰 항목의 `secret` 칸), 그러면 그 채널은 그 열쇠로만 갱신한다.
열쇠 고르는 순서(`ytcore.clientFor`): 토큰 항목의 전용 파일 > 내장 열쇠로 연결했다고 적힌 토큰(`client: "내장"`) > 데이터 폴더의 `client_secret.json`/`device_secret.json` > 실행 파일에 묶인 열쇠.
**옛 판에서 올라온 토큰은 항상 전용 파일을 가리키게 옮긴다** — 다른 열쇠로 갱신하면 토큰이 죽기 때문에, 기본 열쇠로 바꿔 끼우지 않는다.

업로드 한도(하루 10,000점 = 영상 6개)는 **구글 클라우드 프로젝트 단위**로 주어지므로, 한도가 중요한 사용자는 내 열쇠를 만들어 쓰면 된다 — 안내서 부록 A.
동의 화면을 **테스트** 상태로 두면 로그인이 7일마다 풀리므로 반드시 **프로덕션으로 게시**하도록 안내문에 강조해 두었다.

## 인스타그램·스레드 올리기 (선택 기능)

- 유튜브 심사 흐름이 영상을 공개로 돌리는 때(`review.ts`)에 `metapost.enqueue/markPublic` 이 이어받아, 공개가 확인된 쇼츠만 릴스·스레드로 올린다. `tick.ts` 맨 끝 단계(⑨)가 대기분을 올린다. 실패는 유튜브 쪽에 번지지 않는다.
- **큰 영상은 줄여서 올린다**: 규격 위반이 용량·가로세로 크기·비트레이트·코덱·프레임·오디오 코덱처럼 다시 인코딩으로 풀리는 것뿐이면 `enqueue` 는 건너뛰지 않고 원본 사본(`메타대기/<id>.원본…`)을 두고 일감에 `shrink`(대기→줄이는중→끝/실패)를 단다. 길이·가로 영상·알 수 없는 형식은 그대로 건너뛴다. `enqueue` 는 인코딩하지 않는다 — `run`(tick ⑨)이 한 번에 한 편만 `<id>.줄이는중.mp4` 로 만들고(맥은 `h264_videotoolbox` → 실패하면 `libx264`), 다시 재서 규격에 맞으면 `<id>.mp4` 로 이름을 바꾼다. 줄이는중 상태로 끊긴 일감은 임시 파일을 지우고 처음부터 다시 한다. ffmpeg 가 없으면 「영상이 커서 줄여야 하는데 ffmpeg 가 없습니다」로 건너뛴다. 원본은 건드리지 않는다. 시험은 가짜 인코더(`setTranscoderForTest`)만 쓴다.
- `requested_at`·`done_at`·`at` 은 run 시작 시각이 아니라 사건 직전·직후의 실제 시각이다(`stamp(ctx)`, 시험은 `clock` 을 끼운다). 결과 불명 확인 창(요청 시각 −5분)은 그대로. 임시 보관본은 2xx·404 일 때만 「지움」으로 적고, 아니면 `delete_why` 를 남겨 10분 간격 3번까지 다시 지운다.
- **연결 정보**: 실행 파일에 묶인 `meta.json`(`worker_url` · `ig_app_id` · `th_app_id`). 앱 비밀은 어디에도 없고 중계 서버에만 있다. 이 파일이 없는 판은 화면에서 이 기능이 숨는다. 빌드 때 열쇠 폴더에서 `build.sh` 가 구글 열쇠와 같은 방식으로 묶고, `점검.sh` 가 값이 추적 파일에 새지 않았는지 본다.
- **중계 서버**: `worker/meta-auth/`. 로그인 코드→토큰 교환(앱 비밀이 필요한 한 단계) · 토큰 5분 일회 전달(`/pickup`) · 영상 1시간 임시 보관 · 연결 해제/삭제 콜백. 소유자가 할 일 순서는 `worker/meta-auth/README.md`.
- **운영 방식(앱 심사 없이 개발 모드)**: 사용 신청(이메일)을 한 사람만 소유자가 메타 앱 시험 사용자로 초대하고, 그 사람이 수락해야 연결된다(소유자가 할 일은 `worker/meta-auth/README.md` 6번). 신청 이메일·메일 문안·초대 수락하는 곳은 `meta.ts` 의 `신청` **한 곳**에서만 정하고, 화면(`meta/get` 답의 `apply` → `t4.js`)과 오류 안내가 그것을 읽는다(시험이 다른 파일에 글자로 베끼지 않았는지 본다).
  로그인 오류: 중계가 메타의 `error` · `error_reason` · `error_description` 을 가려서 `/meta/done?…&error=&reason=&why=` 로 넘기면(state 없이 거절만 오면 중계가 자기 화면에서 까닭을 말한다), 앱 `explainLogin` 이 ① `reason=user_denied` → 「연결을 취소했습니다」 ② 취소 이름(`access_denied`·`user_denied`)만 오고 까닭이 없으면 취소 + 신청 확인 한 줄 ③ `exchange_failed` → 토큰 교환 실패 그대로 ④ 그 밖의 모든 오류(알 수 없는 이름 포함) → 「아직 사용 신청이 안 된 계정이거나 초대를 수락하지 않았을 수 있습니다」 + 신청 안내 로 가른다. 메타가 자기 화면에서 오류를 보여 주고 돌아오지 않으면 10분 시간 초과 안내에 같은 확인 문구가 붙는다. 오류 글의 토큰·코드 값은 `worker/meta-auth/src/scrub.ts` 의 `오류글` 이 가린다(중계·앱이 같은 함수를 쓴다 — 중계 판이 낡았어도 앱이 한 번 더 가린다).
- 인스타그램 로그인 방식에는 이어올리기(`rupload`)가 없어 릴스는 공개 `video_url` 이 필요하다 — 그래서 인스타그램도 중계 서버의 임시 보관을 거친다. 스레드 영상은 방금 올린 인스타그램 `media_url` 을 먼저 쓰고, 컨테이너가 실패하면 임시 보관 주소로 한 번 더 시도한다.
- **두 번 안 올림**: 게시 호출 전에 `게시요청중` 을 먼저 적고, 응답을 모르는 채 끝난 것은 `결과불명` 으로 두며 자동으로 다시 보내지 않는다(읽기 전용 확인과 사람의 「올라갔음 / 안 올라갔음」만).
- **R2 무료 한도 자동 멈춤**: R2 에는 과금 상한이 없어서 중계가 스스로 멈춘다. `worker/meta-auth/src/ledger.ts` 의 Durable Object 한 개(SQLite 저장소 · 무료 플랜 가능)가 이번 구간의 Class A(올리기 3건 예약·목록)·Class B(읽기)·하루 최고 보관량을 *호출하기 전에* 적고, 무료 한도의 80%(`R2_CAP_RATIO`)에 닿으면 `/stage/ticket` 이 `503 monthly_free_cap`(+ 다시 열리는 시각)으로 거절하고 `/s/…` 읽기는 403 으로 막는다. 동시 보관 총용량(`R2_STAGE_MAX_BYTES` 기본 2GB)이 찬 것은 일시적인 `429 stage_full`. 지우기·크론 청소는 멈추지 않고, 장부가 없거나 고장나면 임시 보관을 열지 않는다. 앱(`metapost.ts`)은 `monthly_free_cap` 을 받으면 그 영상의 인스타·스레드를 실패가 아니라 「대기 — 이번 달 무료 한도 도달, N월 N일에 다시 열림」으로 두고 그 시각까지 중계를 부르지 않는다(유튜브 쪽은 그대로). 숫자·문턱·청구 구간(`R2_CYCLE_DAY`)·`GET /usage` 보는 법·클라우드플레어 예산 알림 거는 법은 `worker/meta-auth/README.md` 의 「R2 무료 한도 자동 멈춤」. wrangler.toml 에 `LEDGER` 바인딩·`migrations`(`new_sqlite_classes`)·변수 세 개가 있어야 임시 보관이 열린다.
- 시험은 가짜 메타·가짜 중계·가짜 R2 만 쓴다: `논리시험.ts 메타` · `논리시험.ts 메타중계` (`시험/메타.ts` · `시험/메타중계.ts` · `시험/가짜메타.ts`). 진짜 메타 서버는 한 번도 부르지 않는다.
