# 가라사대 업로더 — 개발 문서

지정한 폴더에 영상 파일이 저장되면 유튜브에 자동으로 올려주는 프로그램.
맥·윈도우 모두 동작하며, 받는 사람은 아무것도 설치하지 않아도 된다.

## 구조

```
app/            Deno 소스
  main.ts       진입점 (서버 + 감시 시작, 중복 실행 방지)
  paths.ts      크로스플랫폼 경로 · 설정 · 상태 · 로그
  auth.ts       구글 OAuth 2.0 (루프백 + PKCE, 오류 메시지 한국어화)
  youtube.ts    resumable 업로드 (조각 전송 · 중단 지점 이어올리기)
  watcher.ts    폴더 감시 엔진 (저장 완료 판정 · 재시도 · 한도 관리)
  platform.ts   OS 알림 · 폴더 열기 · 자동 시작 등록
  server.ts     로컬 웹 API
  ui.html       웹 화면 (감시/기록/설정/시작하기)
배포/           배포 zip 에 동봉되는 안내문
dist/           빌드 결과물 (build.sh 가 생성)
build.sh        3개 플랫폼 빌드 + 코드서명 + 압축

index.html          (구버전) 브라우저에서 직접 올리는 수동 업로더
start.command       (구버전) 위 화면을 localhost 로 띄우는 실행기
_python_legacy/     (구버전) 파이썬 + launchd 감시 데몬. 맥 전용
```

## 문서

- [설정 안내서](설정안내.md) — 배포 대상자에게 링크로 보내는 설정 안내. 자주 막히는 세 지점을 표시해 두었다.

## 개발

```bash
deno run -A app/main.ts              # 화면까지 열림
deno run -A app/main.ts --background # 브라우저 없이
```

## 빌드 · 배포

```bash
./build.sh
```

맥에서 실행해도 윈도우용 `.exe` 까지 함께 나온다. `dist/*.zip` 을 그대로 배포하면 된다.

| 파일 | 대상 |
|---|---|
| `garasadae-uploader-mac-apple-silicon.zip` | M1 이후 맥 |
| `garasadae-uploader-mac-intel.zip` | 2020년 이전 인텔 맥 |
| `garasadae-uploader-windows.zip` | 윈도우 10 / 11 (64비트) |

**이름을 바꾸지 말고 그대로 올린다.** 자동 업데이트가 이 이름으로 내려받기 때문에
(`app/update.ts` 의 `assetName()`), 이름이 어긋나면 배포는 되는데 업데이트만 조용히 멈춘다.
`build.sh` 가 마지막에 `update.ts` 와 이름을 대조해 다르면 빌드를 세운다.

```bash
gh release create v1.2.3 --title "가라사대 업로더 1.2.3" \
  --notes-file 배포/릴리스노트_1.2.3.md dist/*.zip
```

### 주의사항

- 맥 번들 안의 실행파일 이름은 반드시 **ASCII** 여야 한다 (`GarasadaeUploader`).
  한글 이름을 쓰면 코드서명 봉인이 깨져 `a sealed resource is missing or invalid` 가 난다.
  `.app` 폴더 이름 자체는 한글이어도 된다.
- 애드혹 서명이라 공증(notarization)은 되어 있지 않다. 공증하려면 애플 개발자 계정(연 $99)이 필요하다.
  - **macOS 15(Sequoia)부터 「오른쪽 클릭 → 열기」 우회가 없어졌다.** 뜨는 창은
    「'가라사대 업로더'을(를) 열지 않음」 이고 버튼이 **[휴지통으로 이동] · [완료]** 둘뿐이라 열 길이 없다.
    받는 사람은 **[완료]** 를 누른 뒤 **시스템 설정 → 개인정보 보호 및 보안** 아래쪽의
    **[무시하고 열기]** 를 눌러야 한다.
  - macOS 14 이하는 여전히 **오른쪽 클릭 → 열기** 로 넘어간다. 윈도우는 **추가 정보 → 실행**.

### 그 창의 뿌리는 서명이 아니라 「격리 표」다 (2026-09-02 실측)

Gatekeeper 가 앱을 검사하는 방아쇠는 파일에 붙은 **`com.apple.quarantine` 확장속성(격리 표)** 이다.
이 표를 붙이는 것은 **앱이 아니라 받아 온 프로그램**이다.

| 어떻게 받았나 | 확장속성 | 결과 |
|---|---|---|
| 크롬으로 zip 내려받기 | `com.apple.quarantine: 0281;…;Chrome` + `com.apple.provenance` | 「열지 않음」 창이 뜬다 |
| `curl` 로 내려받기 | `com.apple.provenance` **하나뿐** | 창이 뜨지 않는다 |

즉 **공증에 돈을 쓰지 않아도, 격리 표가 안 붙게 받으면 창 자체가 뜨지 않는다.**
그래서 첫째 길은 터미널 한 줄이다.

```
curl -fsSL https://beautifulahin.github.io/garasadae-uploader/install.sh | bash
```

- 그 한 줄이 실행하는 것이 **`docs/install.sh`** 다.
  다만 **그 주소는 `docs/` 가 아니라 `gh-pages` 가지에서 나온다** — 아래 「문서 사이트」 항목을 볼 것.
  칩 판별(로제타 안에서도 `sysctl -n hw.optional.arm64` 로 진짜 하드웨어를 본다) → `curl -fL` 로 받기
  → `ditto -x -k` 로 풀기(권한·서명 보존, `unzip` 이면 깨진다) → `/Applications` 에 `ditto` 로 놓기
  → `xattr -dr` 안전벨트 → `open` 까지 한다.
  이미 깔린 앱은 **지우지 않고** `~/.가라사대업로더_이전/<날짜_시각>/` 로 옮긴다.
- **릴리스를 새로 올려도 `install.sh` 는 손댈 필요가 없다.**
  버전 없는 `releases/latest/download/<자산이름>` 주소를 쓰기 때문에 늘 최신을 받는다.
  자산 이름을 바꾸면 그때만 같이 고친다(= `build.sh` · `app/update.ts` 와 같은 이름).
- **앱을 다시 구울 필요도 없다.** `install.sh` 는 지금 올라가 있는 릴리스(v1.8.1)를 그대로 받아 깐다.
  한 줄 설치를 살리는 데 필요한 것은 `install.sh` 를 문서 사이트에 올리는 것 하나뿐이다.
- **파이프로 bash 에 먹이므로 `read` 로 사용자 입력을 받으면 안 된다** — stdin 이 스크립트 자신이다.
  그리고 bash 는 변수 이름에 한글을 쓸 수 없어 `"「$APP_NAME」"` 처럼 쓰면
  `APP_NAME」` 을 변수로 읽어 `set -u` 에서 죽는다. 반드시 `${APP_NAME}` 로 감싼다
  (2026-09-02 실제로 이 버그가 났고 시험에서 잡았다).
- zip 을 이미 받은 사람을 위해 맥 배포물에는 `배포/열기.command` 를 계속 함께 넣는다
  (build.sh 의 「안내문 동봉」 단계). `xattr -dr com.apple.quarantine` 로 격리 표만 벗기고 `open` 한다.
  더블클릭으로 돌아야 하므로 **실행권한 755 를 반드시 유지**한다 —
  zip 은 권한을 보존하는 `zip` 명령으로 묶는다.
- 문서에 적은 차례는 어디서나 같다: **① 한 줄 설치 → ② 열기.command → ③ 손으로 4단계 → ④ 옛 맥(14 이하)**.
  (`README.md` · `docs/index.html` · `docs/설정안내.md` · `docs/errors.html` · `배포/맥_처음읽어주세요.txt`)

## 문서 사이트 — `docs/` 가 아니라 `gh-pages` 가지다

`https://beautifulahin.github.io/garasadae-uploader/` 의 소스는 **`gh-pages` 라는 딴 가지**다
(깃허브 Pages 설정: `branch: gh-pages, path: /`). **`main` 의 `docs/` 폴더가 아니다.**

```
gh-pages 에 든 것 : .nojekyll · index.html · errors.html · privacy.html · terms.html
```

- **2026-09-02 이전에는 사람이 손으로 옮겼다.** 옮기는 절차가 어디에도 적혀 있지 않았고
  (`.github/workflows` 없음 · 문서에 gh-pages 언급 0건), 그래서 `main` 의 `docs/` 를 고쳐도
  사이트는 낡은 채로 남았다. 이번 「열지 않음」 사고가 커진 한 축이 이것이다.
- **이제 `릴리스.sh` 가 자동으로 올린다.** `gh release create` 가 끝난 **뒤에**
  `docs/*.html` 과 `docs/install.sh` 를 `gh-pages` 에 올린다.
  - `git worktree` 로 `gh-pages` 를 임시 폴더에 붙여 쓰고 끝나면 뗀다 —
    **작업 폴더의 가지를 갈아타지 않는다.**
  - `.nojekyll` 은 건드리지 않는다. 바뀐 것이 없으면 커밋하지 않는다.
  - 여기서 실패해도 **이미 올라간 릴리스는 되돌리지 않는다.** 손으로 올리는 명령을 한글로 찍고 끝낸다.
- 그래서 `install.sh` 를 고쳤으면 **릴리스를 한 번 돌려야** 주소에 반영된다.
  릴리스 없이 문서만 급히 올려야 하면 `릴리스.sh` 가 찍어 주는 명령을 그대로 손으로 치면 된다.

## 사용자별 구글 설정

업로드 한도(하루 10,000점 = 영상 6개)가 **구글 클라우드 프로젝트 단위**로 주어지기 때문에,
사용자마다 자기 프로젝트를 만들어 쓰는 구조로 되어 있다.
앱의 **시작하기** 탭이 그 과정을 단계별로 안내한다.

동의 화면을 **테스트** 상태로 두면 로그인이 7일마다 풀리므로,
반드시 **프로덕션으로 게시**하도록 안내문에 강조해 두었다.
