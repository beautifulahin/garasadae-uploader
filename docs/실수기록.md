# 실수 기록

같은 실수를 되풀이하지 않기 위해 실제로 냈던 오류와 그 원인, 재발을 막는 방법을 남긴다.
**빌드할 때 `점검.sh` 가 자동으로 돌며 아래 항목들을 검사한다. 통과하지 못하면 빌드가 멈춘다.**

---

## 1. 화면 스타일을 통째로 잃어버림 (2026-08-19)

**증상** — 팝업 세 개가 본문에 그대로 나열되고, 눌러도 아무 반응이 없어 보였다.

**원인** — 여러 채널 화면을 새로 만들면서 기존 `<style>` 을 옮길 때
`re.search(r'<style>.*?</style>')` 로 **첫 번째 묶음만** 가져왔다.
파일에는 `<style>` 이 두 개였고, 두 번째에 있던 규칙 53개(`.modal`, `.dash`, `.panel`,
`.howto`, `.tro` 등)가 사라졌다. `.modal{display:none}` 이 없으니 팝업이 숨지 않았다.

**막는 법** — 점검 2번: 필수 CSS 규칙 38종이 있는지, `style` 블록 중괄호가 맞는지,
`.modal` 이 기본으로 숨겨지는지 검사한다.

**교훈** — 파일을 옮길 때 `findall` 로 전부 가져왔는지 확인한다. 옮긴 뒤에는
결과물에 필수 요소가 남아 있는지 반드시 검사한다.

## 2. 인증 실패를 파일 문제로 잘못 분류 (2026-08-19)

**증상** — 클라이언트 ID·비밀번호가 틀리면 재시도 3번을 소모하고 영상을 `_실패` 로 옮겼다.

**원인** — `auth.ts` 가 평범한 `Error` 를 던져 `watcher` 가 `fatal` 로 취급했다.

**막는 법** — 오류 종류를 `errors.ts` 로 분리하고, 인증 실패는 `config` 로 던진다.
`config` 는 재시도를 소모하지 않고 원본 파일도 건드리지 않는다.

---

## 3. 날짜를 세계표준시로 계산 (2026-08-19)

**증상** — 새벽 0~9시 사이에 "오늘 올린 개수"와 하루 한도가 하루 어긋났다.

**원인** — `new Date().toISOString().slice(0,10)` 은 세계표준시 날짜다.
한국은 9시간 빠르므로 새벽에는 어제로 계산됐다.

**막는 법** — `localDate()` · `localStamp()` 로 이 컴퓨터 시간 기준을 쓴다.
점검 7번이 오늘 날짜로 이전(마이그레이션)을 돌려 개수와 쿼터가 이어지는지 확인한다.

## 4. 업데이트 후 프로그램이 다시 켜지지 않음 (2026-08-18)

**원인** — 옛 프로그램이 살아 있는 동안 새 프로그램을 켜서, 새 쪽이
"이미 실행 중"으로 판단해 스스로 종료했다.

**막는 법** — 완전히 꺼진 뒤에 켠다(`sleep` 후 실행). 화면은 서버가 살아나면 자동 새로고침한다.

## 5. 배포본이 자기 버전을 1.0.0 으로 보고 (2026-08-18)

**원인** — 버전 문자열이 소스와 빌드에 따로 있었다.

**막는 법** — `APP_VERSION` 한 곳에서만 관리하고 `build.sh` 가 그것을 읽는다.
점검 6번이 확인한다.

## 6. 구글 API 호출 한도 초과 (2026-08-18)

**원인** — 업데이트 확인에 `api.github.com` 을 썼다. IP 당 시간 60회 제한이 있어
같은 인터넷을 쓰는 사람이 여럿이면 막힌다.

**막는 법** — 릴리스 최신 주소가 태그 주소로 넘겨주는 것을 이용한다. 제한이 없다.

---

## 7. 로그인 콜백 주소에 경로를 붙임 (2026-08-18)

**원인** — 구글은 루프백 리디렉션에 경로를 허용하지 않는다.
`http://127.0.0.1:8777/oauth/callback` 은 차단되고 `http://127.0.0.1:8777` 만 통과한다.

**막는 법** — 루트에서 `code` 파라미터가 있으면 콜백으로 처리한다.
어느 채널인지는 `state` 파라미터에 실어 보낸다.

---

## 8. 시험이 실제 사용 중인 것을 건드림 (2026-08-18)

**증상** — 시험용 파일이 실제 감시 폴더에 들어가 진짜 채널에 업로드됐다.

**막는 법** — `GARASADAE_DATA_DIR` 로 설정 폴더를 분리하고 별도 포트를 쓴다.
`시험실행.sh` 가 그 역할을 한다. 실제 앱(8777)과 실제 폴더는 시험에 쓰지 않는다.

## 9. 배포 전에 버전을 미리 올림 (2026-08-19)

**증상** — 배포된 최신은 1.6.0인데 소스만 1.7.0이 되어 어느 것이 실제 버전인지 헷갈렸다.

**원인** — "배포할 때만 버전을 올린다" 는 규칙을 정해놓고, 기능을 만들면서 미리 올렸다.

**막는 법** — 만드는 동안 `APP_VERSION` 을 건드리지 않는다. 배포 지시를 받은 시점에
한 번만 올리고 릴리스한다. 릴리스 노트 원고는 `배포/릴리스노트_다음버전.md` 로 두고,
올릴 때 번호를 붙인다.

## 10. 윈도우용 압축파일의 한글 이름이 깨짐 (2026-08-19)

**증상** — 윈도우 사용자가 받은 압축을 탐색기로 풀면
「지정된 파일을 찾을 수 없습니다」가 뜨고 풀리지 않았다. 반디집·7-Zip 으로는 풀렸다.

**원인** — 맥의 `zip` 명령은 한글 이름을 UTF-8 로 넣으면서
**「이름이 UTF-8 이다」 표시(범용 플래그 11번 비트)를 켜지 않는다.**
한국어 윈도우 탐색기는 그 표시가 없으면 CP949 로 읽어 이름이 깨지고,
깨진 이름에 윈도우가 못 쓰는 문자가 섞여 풀기가 실패한다.
맥의 `zip` 은 애플이 손 본 옛 버전이라 `-UN=UTF8` 옵션 자체가 없고, `ditto` 도 켜주지 않는다.

**막는 법** — 윈도우용 압축은 파이썬 `zipfile` 로 만든다 (플래그를 제대로 켠다).
맥용은 `.app` 의 실행권한·서명 파일을 보존해야 하므로 `zip` 명령을 그대로 쓴다.
`build.sh` 가 압축 직후 모든 항목의 플래그를 검사해, 하나라도 안 켜졌으면 빌드를 멈춘다.
