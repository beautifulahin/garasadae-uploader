# 인스타그램·스레드 로그인 중계 (Cloudflare Worker)

가라사대 업로더가 인스타그램 릴스·스레드에 자동으로 올릴 때 쓰는 작은 중계 서버다.
사용자는 앱에서 「인스타그램 연결」·「스레드 연결」을 누르고 로그인만 하면 된다. 아래 일은 **앱 소유자가 한 번만** 하면 된다.

## 왜 필요한가

- 메타 앱의 「앱 비밀」은 누구나 받아 가는 실행 파일 안에 넣을 수 없다. 로그인 코드를 토큰으로 바꾸는 한 단계(앱 비밀이 필요한 유일한 단계)만 이 중계가 한다.
- 인스타그램 로그인 방식은 영상을 직접 올리는 길(이어올리기)이 없고 **메타가 가져갈 수 있는 공개 영상 주소**가 있어야 한다. 그래서 이 중계가 영상을 1시간 이하로만 임시 보관(R2)하고 서명된 읽기 주소를 준다.
- 토큰을 쓰는 모든 호출(올리기·갱신)은 앱이 메타로 직접 한다. 중계는 토큰을 5분 넘게 갖지 않는다.

## 길

| 길 | 하는 일 |
|---|---|
| `GET /ig/start` · `/th/start` | 앱이 연 브라우저가 처음 닿는 곳. 서명한 state 를 만들어 메타 로그인 창으로 보낸다 |
| `GET /ig/callback` · `/th/callback` | 메타가 로그인 뒤 돌려보내는 곳. 코드를 장기 토큰으로 바꿔 KV 에 5분만 두고, 브라우저는 `http://127.0.0.1:<포트>/meta/done` 으로 돌려보낸다 (**주소에 토큰을 싣지 않는다**). 메타가 거절(`error` · `error_reason` · `error_description`)을 알려 오면 토큰·코드 값을 가려(`src/scrub.ts`) 같은 주소로 `error` · `reason` · `why` 만 넘긴다. state 없이 거절만 오면 돌려보낼 곳을 몰라 중계 화면에서 까닭을 말한다 |
| `POST /pickup` | 앱이 verifier 를 보여 주고 토큰을 한 번만 받아 간다 (받으면 바로 지운다) |
| `POST /stage/ticket` · `/stage/delete` | 영상 임시 보관: 일회용 업로드 주소를 주고, 올린 뒤 지운다 (사용자 한 명 하루 40번 · **R2 무료 한도의 80%에 닿으면 거절** — 아래 「R2 무료 한도 자동 멈춤」) |
| `GET /s/<번호>.mp4` | 메타 서버가 영상을 가져가는 서명된 읽기 주소 (1시간 · 읽기 횟수도 장부가 센다) |
| `GET /usage` | 이번 구간 R2 사용량 장부 (관리용 · 서명한 10분 토큰이 있어야 한다) |
| `POST /ig/deauthorize` · `/th/deauthorize` | 메타 「연결 해제 콜백」 |
| `POST /ig/delete` · `/th/delete` | 메타 「데이터 삭제 요청 콜백」 (응답으로 `/deletion?code=` 상태 쪽 주소를 돌려준다) |

## 소유자가 할 일 (순서대로)

### 1. 메타 개발자 앱 만들기

1. https://developers.facebook.com 에서 앱을 만든다 (유형: 비즈니스 또는 「기타」).
2. 인스타그램 쪽: 앱에 **Instagram** 제품(「인스타그램 로그인을 통한 API」)을 추가한다. 권한은 `instagram_business_basic` · `instagram_business_content_publish`.
3. 스레드 쪽: 앱에 **Threads API** 사용 사례를 추가한다. 권한은 `threads_basic` · `threads_content_publish`.
   - 인스타그램과 스레드는 앱 번호·앱 비밀이 각각 따로 나온다 (제품 설정 화면에 보인다). 메모해 둔다: `IG_APP_ID` · `IG_APP_SECRET` · `TH_APP_ID` · `TH_APP_SECRET`.
4. 각 제품 설정에 주소를 등록한다 (`<중계 주소>` = 아래 4번에서 정해지는 `PUBLIC_URL`):
   - 유효한 OAuth 리디렉션 URI: `<중계 주소>/ig/callback` (인스타그램) · `<중계 주소>/th/callback` (스레드)
   - 연결 해제 콜백 URL: `<중계 주소>/ig/deauthorize` · `<중계 주소>/th/deauthorize`
   - 데이터 삭제 요청 URL: `<중계 주소>/ig/delete` · `<중계 주소>/th/delete`
5. 앱 설정 → 기본: 개인정보처리방침 URL 에 이 저장소의 `docs/privacy.html` 이 게시된 주소를, 이용약관에는 `docs/terms.html` 주소를 넣는다. 앱 아이콘·카테고리도 채운다.

### 2. 클라우드플레어 준비

※ 무료 한도 장부(Durable Object)는 따로 만들 것이 없다. `wrangler.toml` 의 `[[durable_objects.bindings]]` · `[[migrations]]` 가 배포할 때 저절로 만든다(아래 4번).

```
cd worker/meta-auth
wrangler kv namespace create META_KV          # 나온 id 를 wrangler.toml 의 kv_namespaces 에 적는다
wrangler r2 bucket create garasadae-meta-stage # 공개 접근을 켜지 않는다 (비공개 그대로)
```

R2 대시보드 → 「R2 API 토큰 관리」에서 이 버킷에만 「객체 읽기 및 쓰기」 권한을 가진 토큰을 만든다. 나오는 액세스 키 ID·비밀 액세스 키를 아래 3번에서 넣는다. 계정 번호(`R2_ACCOUNT_ID`)는 대시보드 주소 또는 오른쪽 위에 보인다.

### 3. 비밀 넣기 (저장소·파일에는 절대 적지 않는다)

```
wrangler secret put IG_APP_SECRET
wrangler secret put TH_APP_SECRET
wrangler secret put SIGN_KEY                 # 아무 긴 글, 예: openssl rand -base64 48
wrangler secret put R2_ACCESS_KEY_ID
wrangler secret put R2_SECRET_ACCESS_KEY
```

### 4. wrangler.toml 의 자리표시자 채우고 배포

`IG_APP_ID` · `TH_APP_ID` · `R2_ACCOUNT_ID` · `META_KV` 의 id · `PUBLIC_URL`(배포되는 주소, 끝에 `/` 없이)을 채우고, **R2 무료 한도 장부 칸**이 들어 있는지 확인한다. 이 칸이 없으면 중계는 임시 보관을 아예 열지 않는다(센 적 없는 R2 호출은 하지 않는다):

```toml
[vars]
# … 위의 값들 …
R2_CAP_RATIO = "0.8"            # 무료 한도의 몇 %에서 새 보관을 멈출지 (0 초과 0.95 이하 · 기본 0.8)
R2_STAGE_MAX_BYTES = "2000000000" # 동시에 보관 중인 영상 총용량 상한(바이트 · 기본 2GB · 무료 용량의 문턱을 넘길 수 없다)
R2_CYCLE_DAY = "1"              # 클라우드플레어 청구 구간이 시작되는 날 (1~28 · UTC · 기본 1 = 달력 월) — 아래 「구간」 참고

[[durable_objects.bindings]]
name = "LEDGER"
class_name = "R2Ledger"

[[migrations]]
tag = "v1"
new_sqlite_classes = ["R2Ledger"]   # 무료 플랜은 SQLite 저장소 Durable Object 만 쓸 수 있다
```

그리고:

```
wrangler deploy
```

배포 뒤 `<중계 주소>/` 를 브라우저로 열어 「가라사대 업로더 로그인 중계」 쪽이 보이면 된다. 이 주소를 위 1-4 의 메타 앱 설정에 등록한다.

### 5. 앱에 연결 정보 묻어 두기

업로더 빌드 때 열쇠 폴더(`배포/.클라이언트경로` 가 가리키는 폴더, 구글 열쇠 `client_secret.json` 이 있는 곳)에 `meta.json` 한 파일을 둔다. **앱 비밀은 넣지 않는다.**

```
{ "worker_url": "https://garasadae-meta-auth.내계정.workers.dev", "ig_app_id": "…", "th_app_id": "…" }
```

`build.sh` 가 이 파일을 실행 파일 옆에 묻는다. 파일이 없으면 앱의 「인스타·스레드 연결」 칸이 화면에서 숨는다 (유튜브 기능에는 영향이 없다). `점검.sh` 가 이 값들이 저장소·문서에 새지 않았는지 확인한다.

### 6. 시험 사용자 초대 (신청 메일을 받을 때마다)

이 앱은 **심사를 받지 않고 「개발 모드」로 운영**한다. 개발 모드인 동안은 앱의 **역할에 넣은 계정(관리자·개발자·테스터)**만 로그인·게시할 수 있다. 사용자는 업로더 설정 화면(「인스타그램·스레드」 칸)의 안내대로 **인스타그램 아이디를 `beautifulahin@gmail.com` 으로 메일**로 신청하고, 소유자가 아래처럼 초대하며, 사용자가 수락해야 연결된다. (신청 이메일·수락하는 곳 문구는 앱 코드 `app/meta.ts` 의 `신청` 한 곳에서 바꾼다.)

신청 메일을 받으면:

- 메타 앱 대시보드(developers.facebook.com) → **앱 역할 → 역할 → 사람 추가**.
  - 인스타그램: 「**Instagram 테스터**」로 그 사람의 인스타그램 아이디를 초대한다.
  - 스레드: 「**Threads 테스터**」로 그 사람의 스레드 아이디를 초대한다.
- 초대받은 사람이 수락해야 한다: 인스타그램은 instagram.com › 설정 › 앱 및 웹사이트 › 「테스터 초대」, 스레드는 스레드 앱 › 설정 › 설정 더 보기(또는 계정) › 웹사이트 권한 › 초대. 수락 전에 로그인하면 메타가 거절하거나 자기 화면에 오류를 띄우고, 앱은 「아직 사용 신청이 안 된 계정이거나 초대를 수락하지 않았을 수 있습니다」와 신청 안내를 보여 준다.
- 계정은 **비즈니스 또는 크리에이터** 계정이어야 한다 (개인 계정은 게시 API 가 막힌다).
- 개발 모드의 테스터 수에는 메타가 정한 상한이 있을 수 있다 — 초대가 막히면 대시보드의 안내를 따른다.

### 7. 앱 심사 (지금은 하지 않는다 — 나중에 신청 없이 누구나 쓰게 열 때만)

현재 운영 방식은 위 6번(심사 없이 개발 모드)이다. 일반 사용자에게 열려면 심사를 통과해야 하고, 그 전에는 6번의 시험 사용자만 쓸 수 있다. 심사에서 보통 요구하는 것:

- 「고급 액세스」를 요청하는 권한마다 사용 설명 + **화면 녹화 영상** (로그인 → 올릴 영상 지정 → 게시되는 과정). 영어 자막 또는 설명이 있으면 좋다.
- 개인정보처리방침 URL (`docs/privacy.html` — 메타 데이터를 어떻게 다루는지 적혀 있다) · 데이터 삭제 요청 URL · 연결 해제 콜백 URL.
- 앱 아이콘(1024×1024) · 카테고리 · 연락처 이메일.
- 사업자 인증(비즈니스 인증)이 요구될 수 있다. 개인 개발자는 시간이 더 걸린다.
- 심사용 시험 계정 안내 (심사자가 따라 해 볼 수 있는 순서).

## R2 무료 한도 자동 멈춤 (`src/ledger.ts`)

클라우드플레어 R2 에는 과금 상한도 자동 정지도 없다. R2 를 쓰는 곳은 이 중계 하나뿐이므로, **중계가 무료 한도 안에서 스스로 멈춰 과금이 생길 수 없게** 한다(R2 요금: <https://developers.cloudflare.com/r2/pricing/> · 표준 저장소 무료 = 저장 10 GB-월 · Class A 월 100만 건 · Class B 월 1,000만 건 · 인터넷 전송은 무료).

### 무엇을 어떻게 세나

| 중계가 하는 일 | 요금 분류 | 장부에 적는 때 |
|---|---|---|
| 앱이 서명된 주소로 올리기(`PutObject`) — 중계를 거치지 않고 R2 로 곧장 감 | Class A | 주소를 내주기 *전에* 3건 예약(올리기 1 + 앱의 다시 시도 2) |
| 메타가 읽어 가기: 머리 확인(`HeadObject`) + 내용(`GetObject`) | Class B | 읽기 전에 2건(HEAD 요청은 1건) |
| 크론의 목록 조회(`ListObjects`) — 10분마다, 쪽당 1건 | Class A | 부르기 전에 1건 |
| 지우기(`DeleteObject`) | 무료 | 적지 않는다 — 한 개씩만 지운다(요금 문서가 무료라고 적은 것은 `DeleteObject` 뿐이고 여러 개 한꺼번에 지우기는 적혀 있지 않다) |
| 보관 용량 | GB-월 = 하루 최고 보관량을 청구 기간(30일)으로 나눈 평균 | 주소를 내줄 때 올리는 사람이 말한 크기를 그날 최고치로 센다. 크론이 R2 에서 실제 크기를 읽어 맞춘다 |

- 숫자는 일부러 **위쪽으로(실제보다 같거나 크게)** 센다. 이 장부는 이 중계가 하는 R2 호출만 안다(같은 클라우드플레어 계정의 다른 R2 버킷·다른 도구가 쓰는 만큼은 모른다).
- **예약 방식**: 호출하기 전에 장부에 적고, 한도를 넘길 호출은 하지 않는다.
- **동시성**: 장부는 Durable Object 하나이고, 한도 판단과 기록이 한 번에 끝난다(`blockConcurrencyWhile`). 동시 요청 둘이 마지막 한 칸을 다퉈도 하나만 통과한다. KV 는 최종 일관성이라 두 요청이 같은 숫자를 읽고 둘 다 통과할 수 있어 쓰지 않았다. 무료 플랜의 Durable Object 는 SQLite 저장소만 되고(`new_sqlite_classes`) 요청 하루 10만 건·쓰기 하루 10만 줄까지 무료다 — 이 중계의 사용량으로는 충분하다.

### 멈추는 문턱 (설정 변수 · 기본값)

| 변수 | 기본 | 뜻 |
|---|---|---|
| `R2_CAP_RATIO` | `0.8` | 무료 한도의 80% — 쓰기 80만 · 읽기 800만 · 보관 8 GB-월. 0 초과 0.95 이하만 받고, 틀린 값은 기본값으로 돌린다 |
| `R2_STAGE_MAX_BYTES` | `2000000000` | 동시에 보관 중인 영상 총용량 2GB. 무료 용량의 문턱(8GB)보다 크게 못 쓴다 |
| `R2_CYCLE_DAY` | `1` | 청구 구간이 시작되는 날(UTC 1~28). 기본은 달력 월 |

- 문턱에 닿으면 `/stage/ticket` 이 **503 + `code: "monthly_free_cap"`**(어느 한도인지 `resource`: `class_a` · `class_b` · `storage`, 다시 열리는 시각 `reopens_at`)를 돌려주고 업로드·읽기 주소를 만들어 주지 않는다. 새 보관을 받을 때는 읽기 여유 20건이 남아 있어야 한다(메타가 읽어 갈 몫).
- 동시 보관 총용량이 찼을 때는 달 한도와 다른 **429 + `code: "stage_full"`** — 보관 중인 영상이 지워지면(보통 몇 분 안) 풀리는 일시적인 막힘이다.
- 읽기 주소(`GET /s/…`)는 읽기(Class B)가 문턱이면 **403**. 지우기(`/stage/delete`)와 크론 청소는 멈추지 않는다. 크론의 목록 조회는 문턱을 넘어도 돌지만, 무료 한도 자체(100%)에 닿으면 목록을 부르지 않는다.
- 장부가 없거나(바인딩 빠짐) 고장나면 임시 보관을 열지 않는다(503 `ledger_unavailable`). 크론은 이때도 낡은 영상을 지운다.
- 앱은 `monthly_free_cap` 을 받으면 그 영상의 인스타·스레드를 실패로 만들지 않고 「이번 달 무료 한도 도달 — N월 N일에 다시 열림」 으로 두고, 그 시각까지 중계를 다시 부르지 않는다. 유튜브 쪽은 그대로다.

### 구간 (달력 월이 맞는지)

요금 문서는 GB-월을 「청구 기간(30일) 동안 하루 최고 보관량의 평균」이라고만 적고, 청구 기간이 달력 월인지 계정의 청구일 기준인지는 적지 않았다(무료 한도는 「매월(each month)」). 그래서 구간 시작일을 `R2_CYCLE_DAY` 로 고를 수 있게 했다. 기본 1 = UTC 달력 월(다음 열림 = 다음 달 1일 00:00 UTC = 한국 시간 09:00). **청구일이 1일이 아니라면 대시보드 Billing 에서 청구 시작일을 확인해 `R2_CYCLE_DAY` 에 맞춰 두는 것을 권한다** — 어긋나면 한 청구 구간에 장부 구간 두 개가 걸쳐, 최악의 경우 문턱(80%)의 두 배까지 쓰게 되어 무료 한도를 넘길 수 있다.

### 사용량 보기 (`GET /usage`)

공개되지 않는다. `SIGN_KEY` 로 서명한 **10분짜리 토큰**이 있어야 하고(만료가 1시간보다 멀거나 이미 지났거나 서명이 틀리면 401), 답에는 비밀이 들어 있지 않다. `SIGN_KEY` 는 처음 `wrangler secret put` 할 때 쓴 글 그대로가 필요하다(저장된 비밀은 다시 읽을 수 없다 — 잃었다면 새로 `wrangler secret put SIGN_KEY` 하면 된다. 이미 내준 주소는 1시간이면 모두 만료된다).

```
SIGN_KEY='…처음 넣은 글…'
EXP=$(( ($(date +%s) + 600) * 1000 ))
SIG=$(printf 'usage:%s' "$EXP" | openssl dgst -sha256 -hmac "$SIGN_KEY" -binary | openssl base64 -A | tr '+/' '-_' | tr -d '=')
curl -s -H "Authorization: Bearer $EXP.$SIG" "<중계 주소>/usage"
```

### 클라우드플레어 청구 알림 거는 법 (소유자용 · 두 번째 안전망)

위 장치가 첫 번째 방어선이고, 그래도 청구가 생기면 바로 알 수 있게 **예산 알림**을 건다. 클라우드플레어 대시보드 → **Manage Account → Billing → Billable Usage → Create budget alert** → 이름(예: 「R2 지출 경고」) · **Budget threshold (USD)** 에 아주 낮은 금액(예: 1달러) · 알림 받을 이메일 → **Save**. 이 알림은 Pay-as-you-go 계정에서만 되고, 현재 청구 기간의 사용량 기반 요금 합계가 그 금액을 넘으면 이메일 한 번을 보내며 새 청구 기간에 다시 시작한다. **알림일 뿐 사용을 멈추거나 상한을 두지는 않는다**(그 일은 이 장부가 한다). 같은 화면의 Billable Usage 와 R2 개요 화면의 이번 달 사용량을 `/usage` 의 숫자와 가끔 견주어 보면 장부가 실제와 맞는지 알 수 있다. (<https://developers.cloudflare.com/billing/manage/budget-alerts/>)

### 남은 위험

- 올리기는 앱이 R2 로 곧장 하므로 중계는 올라간 크기를 그때 보지 못한다. 말한 크기보다 큰 영상은 다음 크론(10분 안)이 지우지만, 그 사이 최대 영상 하나 크기(주소 하나 = 객체 하나, 5GB 한도)까지 들어갈 수 있다. 이 주소는 이 메타 앱으로 로그인한 계정의 유효한 토큰이 있어야 받는다.
- 앱이 올리다 실패해 다시 시도하는 호출은 예약한 2건을 넘으면 장부 밖이다(주소 하나는 10분만 산다).
- 같은 클라우드플레어 계정의 다른 R2 사용은 이 장부가 모른다.
- Durable Object 가 하루 무료 한도(요청 10만)를 다 쓰면 장부가 응답하지 않아 임시 보관이 닫힌다(안전한 쪽).

## 확인되지 않은 것 (실제 메타·클라우드플레어로는 시험하지 않았다)

- 무료 한도 장부는 가짜 저장소·가짜 R2 로만 시험했다. 진짜 Durable Object 의 `blockConcurrencyWhile` 직렬화, 진짜 R2 의 `list` 크기 필드, 진짜 청구 구간 시작일은 배포한 뒤 `/usage` 와 대시보드로 확인한다.

- 콜백 요청 형식: 연결 해제·삭제 콜백은 `signed_request`(앱 비밀로 HMAC-SHA256 확인)로 가정했다. 심사 화면의 「콜백 시험」 단추로 한 번 확인한다.
- KV 는 최종 일관성이라, 아주 드물게 같은 토큰이 두 번 가져가질 가능성이 이론상 있다 (verifier 를 아는 쪽만 가져갈 수 있어 보안에는 영향 없음).
- R2 객체 수명은 크론(10분)으로 지운다. R2 수명 규칙의 최소 단위가 1일이라 규칙 대신 크론을 쓴다.
- 스레드가 방금 올린 인스타그램 영상 주소(`media_url`)를 영상으로 받아 주는지는 실제로 해 봐야 안다. 안 받으면 앱이 자동으로 임시 보관 길로 한 번 다시 시도한다.

## 시험

메타·클라우드플레어를 부르지 않는 가짜 KV·R2·메타 서버로 한다. 저장소 루트(`youtube-uploader`)에서:

```
TZ=Asia/Seoul deno run --allow-read --allow-write --allow-env --allow-net --allow-run --allow-sys --no-lock 논리시험.ts 메타중계
```
